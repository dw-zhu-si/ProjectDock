# Mac App Store 渠道说明

ProjectDock 采用两个相互独立的发布渠道：

| 渠道 | Bundle ID | 本地端口 | 目标能力 |
|---|---|---:|---|
| GitHub 完整版 | `com.zhusi.ProjectDock` | `43110` | 项目启停、真实端口扫描、GitHub 安装、本地扫描与彻底卸载 |
| Mac App Store 沙盒版 | `com.zhusi.ProjectDock.Store` | `43111` | 仅承载通过 App Sandbox 验证的能力 |

小组件分别使用独立 Bundle ID 和 App Group，两个渠道可以同时安装，不会共享设置、项目注册表或组件快照。

## 已验证的发布基础

- `AppStore` 构建配置启用 App Sandbox、Hardened Runtime、用户选择目录读写、出站网络、回环服务和独立 App Group。
- 主应用与小组件能够自动签名归档。
- Xcode 能导出由 `3rd Party Mac Developer Installer` 证书签名的 Mac App Store `.pkg`。
- 沙盒主应用能启动内嵌 `projectctl`，并在 `127.0.0.1:43111` 通过版本健康检查。

这些结果只证明构建、签名和基础进程链可用，不等于商店功能验收或可提交审核。

## 已实施的沙盒边界

完整版本依赖两类沙盒外能力：

1. `/usr/sbin/lsof` 枚举系统 TCP 监听，用于端口真值、项目运行态和小组件快照。
2. Go 子进程直接读取、克隆、启动、停止和删除用户选择的外部项目目录。

商店版已将上述能力从产品和服务端同时关闭：

- 快照、项目列表和小组件不再调用 `lsof`，端口数据以空集表示不可用能力。
- 端口监控、端口分配、Shell 启停、受管日志、外部注册表同步和彻底删除由 HTTP 服务端返回 `501`，前端同时隐藏入口。
- 原生 `NSOpenPanel` 产生应用级安全作用域书签，书签通过本机会话传给 helper，持久化文件权限为 `0600`。
- helper 仅携带 `com.apple.security.app-sandbox` 和 `com.apple.security.inherit`，主应用携带用户选择目录读写和应用级书签权限。
- GitHub 安装使用纯 Go HTTPS ZIP 下载，不调用 `/usr/bin/git`；限制压缩体积、解压体积和条目数，并拒绝路径穿越、符号链接和非普通文件。

## 商店版产品边界

商店版需要使用原生文件访问代理和安全作用域书签管理用户授权目录，并把跨进程文件操作收敛到受授权的原生边界。无法在 App Sandbox 中可靠实现的全系统端口枚举、任意 Shell 命令启停和目录级彻底删除，必须从商店版隐藏并由服务端拒绝；这些能力继续由 GitHub 完整版提供。

上传前的最终验收门禁：

- 用户选择目录在重启后通过安全作用域书签恢复访问（需一次可见的系统目录授权验收）。
- GitHub 下载、项目扫描和登记只作用于用户明确授权的目录。
- 商店版前端不展示端口监控、Shell 启停和彻底删除等不可用操作。
- 仪表盘、项目列表、小组件、AI 设置和 GitHub 安装在沙盒实机运行测试中通过。其中仪表盘/小组件/能力拒绝已自动化通过，目录与 GitHub 完整链等待上述授权验收。
- 隐私政策与支持页在 App Store Connect 填写前返回 HTTP 200。
- App Store Connect 应用记录、隐私问卷、截图、分级、地区和手动发布设置完成。

## 发布资产边界

归档、导出目录和签名包位于忽略的 `work/` 中，不进入源码仓库。任何上传都必须基于重新生成、验证并与 App Store Connect 版本号一致的归档，不能复用仅用于可行性验证的包。

App Store 宣传截屏位于 `assets/app-store/screenshots/zh-Hans/`，共 8 张 2880×1800 PNG，均为无透明通道的 16:10 画面。截屏以真实沙盒版界面为主体，覆盖总览、项目管理、GitHub AI 安装、模型配置、本地扫描、API 工作台、操作审计和 11 种语言；可复现排版模板与真实界面源图保存在同级目录。
